# Отдельные артефакты и перенос

Исходный репозиторий сам по себе не содержит обученных весов и каталога: для распознавания нужен отдельный комплект. Установщик не обращается к неизвестным URL и не скачивает пользовательские данные.

```text
artifacts.json                 # по образцу artifacts.example.json
core-runtime/                  # полная папка frozen runtime, включая models/assets/gallery/descriptor-arrays
frozen-environment.tar         # docker save зафиксированного окружения Core
asset-store/                   # изображения, на которые ссылается БД
database.dump                  # PostgreSQL custom dump, без ролей и владельцев
annotation-gallery/            # галерея .runtime/v5-rc1 для помощников разметки
supplemental/                  # относительные пути от корня репозитория:
  vinedetect_api/data/          # сохраненные коррекции каталога и эталоны
  vinedetect_api/tests/fixtures/
  vision-service/tests/fixtures/
  vinedetect_web/public/assets/
  recognize-service/eng.traineddata
  recognize-service/rus.traineddata
```

Пути в JSON могут быть абсолютными или относительными к самому JSON. Перед переносом копируйте содержимое ссылок (`cp -aL`/`rsync -aL`), а не ссылки на старую машину. `--link` подходит только для локального использования с постоянно доступными источниками.

`provision.py` сверяет SHA-256 каждого файла frozen runtime с публичным манифестом и всех файлов C4 overlay. Docker archive проверяется перед загрузкой; ожидаемый ID образа: `sha256:222c7906258dc4f034f2b90db3c647713a9f1a0e4f2df569f8f40d302bb7bca5`. Затем создаётся локальный тег `vinedetect-core:c4`.

Приложение использует сохранённую схему `svoe_vino,public`, таблицы `roskachestvo` и `meta`. Импортировать нужно полный согласованный снимок. Пустой каталог, созданный одними Python-миграциями, не является заменой снимку. В профиль разметки включён сервис миграции `recognize-migrate`. Не применяйте старые восстановительные скрипты к рабочей БД без отдельного резервного копирования.

Секреты создаются заново на принимающей машине; `.env` не является частью комплекта. Файлы данных после установки игнорируются Git. Учётные записи приложения настроены через окружение; база может содержать историю операторов разметки, поэтому передавать её следует приватно.

Для подготовки нового приватного снимка можно использовать `scripts/create_dataset_snapshot.sh`. Приложенный к задаче документ хранения разметки является справочным контрактом; PostgreSQL и соответствующий asset-store должны переноситься согласованно.

При переносе нового frozen runtime публичный манифест должен обновляться вместе с кодом; установщик намеренно откажется принимать несовпадающие файлы. Исходники в `core/runtime` сохранены для аудита, контейнер исполняет точные байты отдельно поставленного runtime. C4 overlay берётся непосредственно из `core/engineering`.
